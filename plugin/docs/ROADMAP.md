# Roadmap

> Committed line, moved out of session memory 2026-08-19. The versioning rules behind every entry are in [versioning.md](versioning.md) — the 1.x line closed; **the 2.x MCP era shipped 2026-08-21**.

**1.9.2 — this release.** The versioning policy and this roadmap land as in-repo docs, and the README is restyled. One invalid measurement is retired: the latency figure (claiming most max-effort calls exceed four minutes) came from a buggy script and is owner-invalidated (2026-08-19); it is removed from every surface. The cost figures are kept — they were measured by a different script and are not invalidated. No code changes: a docs release is a patch.

**1.9.3 — dispatch gate — shipped 2026-08-19.** A `PreToolUse` hook on the `Agent|Task` matcher: a subagent dispatch whose prompt carries attack intent requires a valid armed scope. This closes the measured hole — ZCode hooks do not fire inside subagents, so the current scope gate never sees what a dispatched agent is about to do (our measurement, 16 verification commands in a real Verifier run, none reached the log). The `Agent|Task` matcher itself is doc-backed (research 20260819-1927). Also ships the projectRoot nested-marker fix (field incident 20260819-2107: a subfolder with its own package.json no longer hides the parent scope).

**1.9.4 — command `skills` auto-mount — shipped 2026-08-19.** The security commands (`/ohmy-security`, `/ohmy-redteam` under their current names) mount the `security-gate` skill themselves, so the doctrine loads without relying on the session hook. Adds `when_to_use` frontmatter on the three skills, and documents the skill-in-subagent caveat for tool-restricted agents (doc-backed, research 20260819-1927). Also ships the bootstrap-poisoning fix (evidence bootstraps at the workspace boundary, not the nearest marker) and default-port target normalization (`example.com:443` now matches implicit-443 URLs).

**1.9.5 — token-matched scope gate — shipped 2026-08-20.** The scope gate matches attack commands on typed tokens from a vendored shell-quote parser (1.10.0, byte-identical, zero runtime dependency) instead of raw substrings — quotes, wrappers, pipes and `$(…)` cannot hide the tool word (measured incident: `grep nuclei …` was blocked as a false positive, 2026-08-19). Adds Windows wrappers/interpreters (`powershell`/`pwsh`/`cmd`) to the POSIX set. Ships `scope_attack_pass` observability — the audit trail now distinguishes attack commands the gate saw pass under an armed scope from subagent-internal commands invisible to hooks by design (the LMS BOOSTER ghost run, resolved). The README gains a guardrail honesty line: the cage raises the bar mechanically, it is not an authorization oracle.

**1.9.x (polish).** Known edges from the v1.9.1 run report: IPv6 target support, and the `exp/` raw-data gap (docs/routing.md references an `exp/` folder of raw measurement data that was never committed).

**2.0.0 — the MCP release — shipped 2026-08-21, defective; the redo moves the tag.** The tag as first published never registered an MCP server. Two measured causes (five experiments + the decisive cold-restart experiment, 2026-08-21): (1) **the MCP loader reads plugin manifests only at app start** — a plugin installed or toggled mid-session never gets its servers registered (the first live-test and every toggle-only experiment showed zero registration events); (2) the tools declared no `inputSchema`, so the spawn failed on `tools/list` once the manifest was finally read. The decisive experiment (2026-08-21 evening: `.zcode-plugin` alone + cold restart → registration with live PIDs) corrected the interim diagnosis — BOTH manifest forms register at cold start; "silently ignored form" was a confound of the toggle-reload limitation. Final form: the release ships the official `.zcode-plugin` form (measured registering at cold start, 2026-08-21 evening); `.claude-plugin` was the interim diagnosis bench, retired for nomenclature — the design choice is the official form BY OWNER RULING (2026-08-21 soir). The redo reshapes the release: arming **by invocation** (`/ohmy-redteam <target>` derives targets+env, writes `active_scope.json` with a 60-minute expiry — no settings panel, no configuration form); the full **OH MY rename** (5 commands `/ohmy-*`, 7 agents `ohmy-*`); **4 writers** (`explorer` read-only recon; `scaffold-writer`/`plan-writer`/`draft-writer` produce artifacts, never verdicts — `/ohmy-plan` and `/ohmy-research` become relay protocols, the orchestrator stops writing); **5 MCP servers** in the manifest (scope stdio + codegraph stdio + semgrep + osv-scanner + grep.app http; `semgrep`/`osv-scanner` are documented binary prerequisites — a spawn failure is isolated); and the `command -v` hook debt retired. codegraph joins the manifest by owner ruling (2026-08-21 nuit) — an efficiency play (research 20260819-0743: measured tool-call reductions, no quality benchmark exists), mounted from a vendored local install (v2 used a Windows-only bootstrap; 3.0.0 uses the cross-platform npm command documented in distribution.md). **Operational law (measured)**: after installing or updating the plugin, restart the app — a session opened without a cold start will not see the plugin's MCP servers. Renamed to `oh-my-zcode` — **breaking**: uninstall `betterzcode` first; a 1.9.5 scope left armed mid-run is disarmed at the first v2 server start. **Documented deviation, unchanged**: no `authorize` tool — `PermissionRequest` cannot distinguish a user call from an agent call, so an agent-callable `authorize` would be self-armable; invocation arming keeps the agent out of the authorization loop by construction — the agent writes the scope file only inside a command the operator deliberately ran. All doc-backed (research 20260819-1927, `.oh-my-zcode/research/20260819-1927_zcode-capabilities-validation_0848e5b7/report.md`).

**2.1.0 — claim/proof typing — shipped 2026-08-21.** Every structured finding now carries a claim type: `behavior` (proven by an executed command against the target) or `source` (proven by git + code reading at the recorded commit). The finding-verifier mechanically rejects a proof that cannot decide its claim's type (`PROOF-TYPE MISMATCH` — new verdict). /ohmy-redteam's surface.md opens with a PROVENANCE block (artifact tested, source commit, working-tree state — raw command outputs). security-gate rule 19: a code comment is not evidence of current state. Beast dispatch prompts are clock-free: minutes, budgets and deadlines are forbidden dispatch text — the beast has no chronometer, a time budget is only pressure that cuts the chain before the data; the ceiling is the orchestrator's maxTurns, invisible to the beast (frozen by test 25.23). Root cause: the 2026-08-21 incident — a measured 404 on a stale-built image was generalized into an unproven source claim, reinforced by a stale code comment, and signed by re-executing the curl.

**2.2.0 — the prize-hunting siege — shipped 2026-08-24.** /ohmy-redteam stops walking WSTG families and starts hunting prizes: read all user data, admin access, code execution. New Step 2.5 writes a white-box `source-map.md` (PROVENANCE-committed, guard diffs as pre-chewed hypotheses) from the session's target repo, degrading to `no source available` for remote targets. Beast dispatches invert — identity + prize + both maps, work backwards from the prize, every capability a tool; wave 2 becomes a mandatory cascade; the run stops on signal (prize proven, or two consecutive waves with no new capability); an expired scope pauses and re-arming resumes from the persisted loot. security-gate rule 20: the beast hunts a prize, never a checklist (Kettle's HTTP Terminator discovery cascade; GLM-5.3 CVD white-box ledger). The report itself is disciplined: rule 21 (a failed attempt proves the attempt failed — never an inferred state claim; evidence: the run-2 AES false negative, corrected by run 3's byte comparison), a root-cause table opening the report (one root, N impacts — never inflated counts) and execution findings naming their exact plane (process, container, credentials — a generic label like RCE is not a report line). Live-proven on kithapp across runs 2 and 3 (three prizes, both waves; run 3 = post-rebuild regression: HTTP fixes held, the committed DB superuser remains the single root). ohmy-security keeps its WSTG family structure by design — scanner vs hunter.

**2.2.1 — named rigor in the build loop — shipped 2026-08-25.** The builder-reviewer pair gains the discipline the rest of the pipeline already had. builder: before writing any validation/predicate/comparison code, ENUMERATE the invalid-input classes the check must reject (structure, cardinality, types, case, unicode homoglyphs/zero-width, duplicates, coercion traps) and implement against that own list — a check closes only the classes it was written against; reviewer reproduction cases are re-run verbatim with results pasted; every call site of a changed symbol is grepped and listed; regression tests load the shipped artifact's own bytes (AST-extract/import/hash-match), never a drifting copy; and a blocked->STOP rule distinguishing a refusal (yours — retry) from a blocker (the world's — stop and report): a stopped task with a clear blocker report is a SUCCESS, a green run that violated a constraint is a FAILURE. reviewer: BLOCKING findings must carry exact runnable reproductions (verbatim inputs, expected outcomes) — a blocker that cannot be turned into a reproduction is downgraded to MAJOR. /ohmy-plan Done-when anchors artifact identity (recorded SHA-256) when the deliverable is re-run or re-deployed; /ohmy-swarm's report checklist gains the artifact-identity line. Root cause pattern: the model implements named rigor, never implied rigor — every rule converts an implied expectation into written, executable text (frozen by tests 25.30).

**2.3.0 — the blind council — 2026-09-21.** `/ohmy-council` submits an idea to five isolated members, blind and undirected: three judges (analyst/skeptic/strategist — criteria stated BEFORE reading the briefing, the reviewer pattern transposed) and two creatives (innovator on the idea; explorer of unexplored territories, who ideates from first principles BEFORE opening the briefing — anti-anchoring, the council's version of criteria-before-code). The briefing is raw material by contract: verbatim quotes and file paths, exhaustive or by pointer, never a selection — a selection is a direction. Aggregation is majority (≥ 2 of 3 judges, evidence-gate rule 8), never union; minority views and split verdicts stay verbatim; the report never recommends. Works at any moment — the orchestrator freezes the current state (raw idea or post-brainstorm). Routing is an UNMEASURED default (judges high by reviewer analogy, creatives max by builder analogy) — marked as such in every member file; full rationale in docs/council.md. No gate, hook or MCP change: `COUNCIL:` is new, non-reserved vocabulary.

**3.0.0 — native Rust and artifact-bound proof — in development, 2026-09-21.** One native executable owns hooks, the scope MCP server and read-only validation. Platform archives contain precompiled binaries with SHA-256 marketplace binding; users do not install Rust. Typed, versioned receipts pair pre/post Bash events by full session identity, tool-use ID, command and cwd. Expected numeric exit/output assertions and source/artifact fingerprints govern PASS and FINDINGS; fresh snapshots must match before execution, after execution and at Stop. Invalid citation claims also remain blocked on retry. Obsolete JavaScript runtimes, vendored shell parser, old scope formats and migration paths are removed. Actual Rust AST gates enforce per-function cyclomatic complexity ≤10, cognitive complexity ≤15, and bounded module/function sizes. Native tests cover the shipped protocol; see [proof.md](proof.md) and [distribution.md](distribution.md). The same day the agent layer caught up with the platform, read at the newly open ZCode source (github.com/zai-org/ZCode): all 17 agents pinned in picker format `providerId/modelId` (a bare model name is silently dropped and `thoughtLevel` dies with it — verified in `subagent-markdown-selection.ts`; until 2.3.0 every agent was unpinned, correct only by session-model coincidence), every seat at `max` by owner setting, per-agent `skills:` mounts each pipeline role with its gate's doctrine, every agent file carries the todo-tracking rule (the platform's native `todo_reminder` does the waking), and the session-start hook appends an update notice when the published marketplace is newer (24h rate limit, fail-open, kill switch). The multimodal locker ships as the 17th agent: `vision` (`GLM-5.3-Flash`, the only multimodal model in the plan) — read-only, one image, WHAT/TEXT SEEN/NOTABLE, never a verdict — with the doctrine's image rule: a text-only session that receives an image never dead-ends, it dispatches vision and answers from its description (frozen by tests 28.1-28.2; Flash multimodality remains to be proven by a live image dispatch — the pin is real, the eyes are untested).
